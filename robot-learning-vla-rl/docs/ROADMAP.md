# 项目 B：项目驱动路线图（候选）

> 当前只批准制定计划，不自动授权下载、安装、训练或付费；顺序优先，时间表可以依结果调整。目标截止 2027-01-15。

| 阶段 | 学习/开发主问题 | 真正的交付物 | 开始下一阶段的门槛 |
|---|---|---|---|
| W1 | LIBERO 观测如何变为 SmolVLA 动作，数据如何产生梯度？ | 已定位的真实源码调用链、Notebook、自测结果 | 能解释数据—模型—loss—动作—环境闭环 |
| W2 | 训练脚本、数据字段和动作表示如何对齐？ | 配置审查、Tensor shape/归一化表、明确依赖与显存风险 | 训练/评测方案、硬件预算经用户同意 |
| W3–5 | 公开 checkpoint 能否稳定闭环评测？是否能开展 SmolVLA 微调？ | 固定版本配置、真实 rollout、训练日志、指标、失败记录 | 基线可复现、无信息泄漏；否则暂停并复核 |
| W6–8 | 哪个可验证的问题最值得修改？ | 一个源码层面技术改动、独立测试、对照/消融 | 实验有效而非仅调超参或描述性想法 |
| W9–10 | SAC 如何通过交互/Replay Buffer/Actor-Critic 学习？ | 一组真实仿真训练与评测结果（需单独授权） | 训练记录完整、理解奖励/探索/失败情形 |
| W11 | 模型是否泛化，实验结果有多稳健？ | 多条件/种子评测、置信区间、失败分析 | 结果可审计；世界模型只补少量源码 |
| W12 | 项目怎样经得住面试？ | README、复现说明、简历版本、演示视频（如实际取得） | 所有成果均有代码和结果支撑 |

## 中止与复核原则
- 任何需要下载大量模型、租 GPU 或开始正式训练的动作，先给备选方案、预计成本、停止条件，由用户批准。
- 公开模型若不能在固定依赖/控制方式下可靠复现，不直接进入算法增益比较；先进行有限范围排查，再由用户决定是否换版本或框架。
- 近期优先求职岗位是 VLA / 机器人 RL；世界模型岗位是附加投递方向，不占用主项目大量训练预算。
- 以上计划不是论文创新承诺，也不是获得 Offer 的概率预测。
