# Codex 项目行为准则（项目 B）

## 目的
帮助用户逐步掌握 LeRobot / SmolVLA / LIBERO 的 VLA 工程，并在后续自主修改算法、执行真实对照实验；RL 后期补充。不是科研项目 A。

## 默认工作模式
1. 每次只处理当前学习日/具体工程问题。先读 `README.md`、`docs/STATUS.md`、`docs/DECISIONS.md`、对应 notebook 当日章节，再定位上游源码。
2. 保持**项目先行**：从真实源码函数、数据 shape、调用关系进入；只有碰到阻碍时才补理论。解释需列出文件路径、函数和可验证证据；不编造已读过的代码或实验结果。
3. 不能直接在没有证据时宣布“原算法存在缺陷”或“个人方法有效”；先列出待验证假设与反例，再提出测试。
4. 对明确获准的小型本地文件修改，允许编辑 `src/`、`tests/`、文档和 Notebook；改动后运行适用的**本地低成本测试**并汇报实际结果。未经用户批准不得执行大量计算、网络下载安装、远程 push 或有成本操作。
5. 不擅自切换 LeRobot 主线、模型/实验任务/版本、算力方案。当前固定版本 `v0.6.1` 只是**源码学习候选**，不是已验证可复现环境。
6. 禁止未经许可的 `pip install`、`git clone` 大型上游仓库、HF 模型/数据下载、训练运行、`git push`、云 GPU 租赁，以及任何可能导致付费的操作。
7. Git 不记录数据集、原始视频、预训练权重、checkpoint、实验缓存、密钥和隐私信息。提交前确认 `.gitignore` 是否生效。
8. 先查看 Git diff；不强推、不覆盖远端未合并工作、不把两个研究项目混在一起。

## 可验证交付要求
- 代码改动：列出路径、输入输出、行为测试与未覆盖边界。
- 实验：记录版本（commit）、数据、随机种子、配置、硬件、成功率/耗时/不确定性、失败案例；没有跑就写“未执行”。
- 学习：解释关键调用链 + 一个能亲自验证的证据 + 仍未知的问题。
- 阶段报告：仅在有真实新结果时更新 `docs/STATUS.md` 和 `notes/weekly/`。
